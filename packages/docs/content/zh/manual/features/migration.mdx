# 启动器迁移

DropOut 可以把现有 Minecraft 环境搬入一个新的托管实例，并保持来源启动器不变。迁移全程只复制：DropOut 只扫描、读取来源目录，所有目标文件都创建在 DropOut 管理的目录中。

## 开始迁移

1. 打开 **实例**，再打开 **实例库操作**，选择 **从启动器迁移**。
2. 选择自动检测到的来源，或手动选择实例、`instances`、`.minecraft`、`versions` 目录，也可以选择受支持的启动器归档包（`.zip`/`.mrpack`）。
3. 选择一个或多个环境。
4. 核对清单，处理重名，并检查 **带走**、**留在原处**、**不支持** 三类内容。
5. 开始传输。你可以取消当前复制；DropOut 会删除本次操作创建的所有目标文件。
6. 阅读兼容性报告。首次启动前完成必需操作，或使用 **撤销导入** 删除已完成的目标实例。

界面始终显示 **发现 → 核对 → 传输 → 报告** 四阶段轨道，明确当前是在读取来源、复制文件，还是等待你的决定。

## 启动器兼容性

| 来源 | 自动发现 | 元数据 | 可迁移游戏内容 | 说明 |
| --- | --- | --- | --- | --- |
| Prism Launcher | Windows、macOS、Linux、Linux Flatpak | 名称、Minecraft 版本、Fabric/Forge/NeoForge/Quilt、备注、图标、Java/JVM/内存覆盖 | 模组、配置、资源包、光影包、存档、截图、服务器、选项 | 会保留 Prism `icons` 目录内的自定义图标。 |
| MultiMC | Windows、macOS、Linux | 名称、Minecraft 版本、加载器、备注、Java/JVM/内存覆盖 | 与 Prism 相同 | 支持包含 `instance.cfg` 或 `mmc-pack.json` 的实例目录。 |
| HMCL | 常见 `.minecraft`/HMCL 位置；所有平台均可手动选择 | 已选版本与加载器元数据 | 全局或版本隔离的模组、配置、资源包、光影包、存档、截图、服务器、选项 | 版本隔离内容优先于全局 `.minecraft` 内容。 |
| PCL 兼容布局 | 常见 Windows `.minecraft` 位置；所有平台均可手动选择 | 已选版本与加载器元数据 | 与 HMCL 相同的全局/隔离规则 | 已选版本 JSON、JAR、native/运行时文件保留在 `versions/<id>`。 |
| 启动器归档包 | 手动选择文件 | 在存在时读取 MultiMC、Modrinth、CurseForge/HMCL-PCL 清单元数据 | 包内的配置、存档、模组、资源包、光影包、截图、服务器和选项 | 支持普通配置/存档 ZIP。清单中的远程依赖会明确标记为后续必需操作，不会被静默视为已安装。 |

自动发现只检查启动器的常规数据位置。便携版和自定义游戏目录请使用 **选择目录**，避免猜测错误路径。

## 理解迁移清单

### 带走

DropOut 会在存在时复制用户拥有、可迁移的内容：

- `mods`、`config`、`resourcepacks`、`shaderpacks`、`saves`、`screenshots`；
- JourneyMap、回放录像、投影、纹理包和服务器资源包；
- `options*.txt`、`servers.dat` 和实例图标；
- 保留 PCL/HMCL 启动配置所需的已选版本档案。

对于 PCL/HMCL 的隔离版本，已选版本目录中的内容优先于对应的全局 `.minecraft` 内容。每一类只选择一个来源复制，避免意外混合全局和隔离模组。

### 留在原处

`assets`、`libraries`、`logs`、`natives`、崩溃报告和启动器缓存等生成或共享数据，不会作为普通游戏内容复制。DropOut 会按需解析共享游戏依赖。属于已选 PCL/HMCL 版本档案的运行时文件仍会随该档案保留。

### 不支持

未知的顶层内容和符号链接会在传输前明确列出，并且不会被跟随。这样可以防止启动器实例让迁移越出已核对的来源目录。如果最终报告指出某个链接目标必不可少，请验证后手动复制目标内容。

归档条目也采用相同规则。绝对路径、父目录穿越、Windows 盘符、重复目标和归档内编码的符号链接都会在解压前拒绝。DropOut 只复制已核对的便携路径，绝不会重写来源归档包。

## 冲突、取消与回滚

- 重名时会给出带来源的建议名称，例如 `Create Live (Prism)`；复制前可以修改目标名称。
- 目标文件绝不会被覆盖。若出现意外目标冲突，当前操作会停止，并回滚本次新建文件。
- **取消并回滚**会回滚当前环境并停止剩余队列；同一队列中已经完成的环境会保留在报告中。
- **撤销导入**会删除已完成的 DropOut 实例，不会触碰原启动器。

## 兼容性报告

每个导入环境都会获得结构化检查：

| 检查 | 已就绪 | 需要操作 |
| --- | --- | --- |
| 游戏版本 | 已识别 Minecraft 版本/档案。 | 首次启动前选择 Minecraft 版本。 |
| 模组加载器 | 已识别原版，或已连同加载器元数据复制所选 PCL/HMCL 版本档案。 | Prism/MultiMC 与归档包导入需在首次启动前安装检测到的 Fabric、Forge、NeoForge 或 Quilt 档案；未知加载器需手动替换。 |
| Java | DropOut 可自动解析 Java，或导入的覆盖路径可用。 | 选择已安装 Java，或清除失效覆盖路径。 |
| 内存 | 导入范围有效，或使用 DropOut 默认值。 | 确保最大内存大于或等于最小内存。 |
| 链接文件 | 没有跳过必需链接。 | 必要时手动复制已验证的链接目标。 |
| 归档包依赖 | 所需内容都已嵌入归档包。 | 在实例内容浏览器中安装报告列出的远程模组和资源包。 |
| 图标 | 已保留来源启动器图标。 | 在实例设置中选择替代图标。 |

**可以验证启动**表示元数据足以进入 DropOut 的常规启动就绪检查，并不表示缺失游戏资源或账户已经准备完成。**需要处理**始终附带明确的下一步。

## 来源安全

迁移 fixture 覆盖原版、Fabric、Forge、重度模组、缺失版本、重名、便携配置/存档包、MultiMC 归档包和 HMCL/CurseForge 归档包。测试会在复制前后对每个目录树或归档包生成指纹，确保来源逐字节不变；同时覆盖路径穿越、链接根目录以及 Windows、macOS、Linux、Linux Flatpak 路径构造。

迁移完成后可继续使用[实例库](/docs/manual/features/instances)，若环境仍需修复，请查看[故障排除指南](/docs/manual/troubleshooting)。
